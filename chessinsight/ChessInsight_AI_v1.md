# ChessInsight AI

## 대화형 체스 코칭 및 실력 분석·자동 리포팅 플랫폼 기획안

-   문서 버전: 1.0
-   작성일: 2026-10-21
-   프로젝트 유형: AI 기반 데이터 분석 및 개인화 코칭 플랫폼

------------------------------------------------------------------------

## 1. 프로젝트 개요

### 1.1 한 줄 정의

ChessInsight AI는 체스 대국의 엔진 분석 결과를 근거 기반 자연어로
설명하고, 여러 대국에 걸친 반복 실수와 약점을 탐지해 개인화 훈련 방향 및
정기 리포트를 제공하는 대화형 체스 코칭 플랫폼이다.

### 1.2 해결하려는 문제

체스 플레이어는 대국이 끝난 뒤 엔진 분석으로 최선의 수와 평가치 변화를
확인할 수 있다. 하지만 엔진의 수치와 변형만으로는 다음 질문에 답하기
어렵다.

-   이 수가 왜 좋은 수인가?
-   내가 선택한 수는 어떤 위협이나 기회를 놓쳤는가?
-   비슷한 실수가 여러 대국에서 반복되고 있는가?
-   최근 한 달 동안 실제로 개선된 영역과 여전히 취약한 영역은 무엇인가?
-   다음에는 어떤 유형의 포지션을 집중적으로 훈련해야 하는가?

기존 분석 도구가 대국별 리뷰와 통계 제공에 강점을 가진다면, 이
프로젝트는 대국별 분석을 장기적인 학습 과정으로 연결하고 사용자가
자연어로 후속 질문을 이어갈 수 있도록 설계한다.

### 1.3 목표 사용자

**초기 타깃** - 체스 초보자부터 중급자까지, 레이팅 향상을 목표로 하는
플레이어 - 엔진 분석 결과를 이해하기 어렵거나 반복 실수의 원인을
파악하고 싶은 플레이어 - 자신의 대국 이력을 체계적으로 복기하고 싶은
플레이어

**확장 타깃** - 학생들의 대국을 검토하는 체스 코치 - 여러 학습자의 취약
영역과 개선 추이를 관리하려는 교육 기관 및 클럽

### 1.4 핵심 가치 제안

1.  **설명 가능한 대국 리뷰:** 엔진이 제시한 최선의 수와 실제 수의
    차이를 구체적인 포지션 근거와 함께 설명한다.
2.  **대국 간 패턴 탐지:** 한 판의 실수에 그치지 않고 여러 대국에서
    반복되는 취약점을 찾아낸다.
3.  **대화형 분석:** 사용자가 "왜 이 수가 나쁜가?", "다른 후보 수는
    어땠나?"와 같은 후속 질문을 할 수 있다.
4.  **개선 추적:** 기간별 분석 결과를 비교해 취약점이 줄었는지, 표본이
    충분한지 확인한다.
5.  **자동 리포팅:** 주간·월간 요약과 다음 훈련 권장 사항을 자동으로
    생성한다.

## 2. 주요 기능

### 2.1 PGN 가져오기 및 대국 관리

-   PGN 파일 업로드를 통한 대국 가져오기
-   지원 API를 통한 사용자 대국 이력 연동
-   플레이어 색상, 결과, 날짜, 오프닝, 레이팅 등 메타데이터 정리
-   대국별 분석 상태 및 진행률 표시
-   중복 대국 및 파싱 오류 처리

초기 버전에서는 외부 플랫폼 연동에 앞서 PGN 업로드를 기본 입력 경로로
제공한다. API 연동은 각 플랫폼의 정책과 호출 제한을 확인한 뒤 추가한다.

### 2.2 엔진 기반 대국 분석

-   Stockfish를 활용한 포지션 평가
-   실제 착수와 엔진 추천 수 비교
-   블런더, 미스테이크, 부정확한 수 등 실수 후보 탐지
-   핵심 국면 및 평가치 변화 표시
-   후보 수와 주요 변형 제공
-   사용자가 특정 수를 선택했을 때의 결과와 대안 비교

실수 분류 기준은 엔진 설정, 분석 깊이, 포지션 특성에 따라 달라질 수
있으므로 기준을 명시하고 일관되게 적용한다.

### 2.3 근거 기반 자연어 해설

각 설명은 엔진 평가와 변형을 기반으로 생성한다.

예시 질문: - "이 수가 왜 실수인가?" - "엔진이 추천한 수를 두면 어떤
위협을 막을 수 있었나?" - "상대가 다음에 노린 것은 무엇인가?" - "추천
수와 내가 둔 수의 차이를 비교해줘."

설명에는 가능한 경우 다음 정보를 포함한다. - 해당 포지션의 핵심 전술
또는 전략적 요소 - 실제 수와 추천 수의 차이 - 주요 후속 변형 - 평가치
변화 - 설명의 근거가 된 포지션과 수순

LLM이 체스 판단을 독자적으로 만들어내도록 하지 않는다. 엔진과 분석
계층이 근거를 산출하고, LLM은 그 근거를 이해하기 쉬운 문장으로 변환한다.

### 2.4 여러 대국의 반복 약점 분석

-   반복되는 전술 실수 유형 탐지
-   오프닝별 성과와 취약 구간 분석
-   중반전·종반전에서의 실수 패턴 분석
-   시간 부족과 실수의 동반 발생 여부 탐색
-   특정 유형의 포지션에서 반복되는 판단 오류 요약
-   표본 수가 적은 패턴에 대한 신뢰도 표시

예시 질문: - "최근 30판에서 가장 자주 반복된 실수는 무엇인가?" -
"종반전에서 패배로 이어지는 패턴이 있는가?" - "백과 흑 중 어느 쪽에서
실수가 더 자주 발생하는가?" - "최근 한 달간 개선된 영역과 악화된 영역을
비교해줘."

이 기능은 단순히 통계를 나열하는 데 그치지 않고, 각 발견을 관련 대국과
수순으로 연결해 사용자가 직접 검토할 수 있게 한다.

### 2.5 기간별 실력 분석 및 자동 리포트

-   주간·월간 성과 요약
-   레이팅 및 승률 추이
-   실수 유형별 빈도 변화
-   오프닝·중반전·종반전별 지표 비교
-   이전 리포트와의 변화 비교
-   개인화 훈련 권장 사항 생성

레이팅 변화만으로 실력 향상을 단정하지 않는다. 상대 수준, 대국 수,
시간제어, 표본 크기 등의 맥락을 함께 표시한다.

### 2.6 개인화 훈련 추천

분석 결과를 바탕으로 훈련 우선순위를 제안한다.

예시: - 반복적으로 놓치는 전술 유형의 퍼즐 훈련 - 특정 오프닝에서 자주
발생하는 포지션 복습 - 종반전 실수가 많은 경우 관련 종반전 학습 추천 -
시간 부족과 실수가 함께 나타나는 경우 시간 관리 훈련 제안

추천은 관찰된 데이터와 연결해 설명하고, 데이터가 부족하면 단정적인 권고
대신 추가 관찰을 제안한다.

### 3.2 경쟁 분석 결론

다음 기능은 이미 경쟁 서비스에서 일부 또는 상당 부분 제공되고 있으므로
단독 차별점으로 내세우지 않는다.

-   엔진 추천 수를 자연어로 설명하는 기능
-   대국별 실수 분석
-   기간별 성과 통계
-   개인화 훈련 제안

차별화는 기능 하나보다 **분석 결과를 장기적인 학습 대화로 연결하는 전체
워크플로**에 둔다.

### 3.3 제안하는 차별화 포지션

1.  **대국 간 패턴을 근거와 함께 설명:** "전술이 약하다"는 요약에서
    끝나지 않고, 반복 패턴이 나타난 대국·수순·포지션을 제시한다.
2.  **자연어 후속 탐색:** 사용자가 분석 결과를 바탕으로 추가 질문을
    이어가고, 특정 주장에 대한 근거를 확인할 수 있다.
3.  **리포트 간 변화 추적:** 지난달에 발견한 약점이 이번 달에 줄었는지,
    데이터가 충분한지 비교한다.
4.  **한국어 학습 경험 최적화:** 체스 용어를 무조건 번역하는 데 그치지
    않고, 초보자와 중급자에게 맞는 설명 수준을 제공한다.
5.  **근거 검증 가능한 설명:** 모든 주요 설명을 엔진 변형, 평가치, 실제
    기보와 연결한다.

이 차별화 가설은 사용자 테스트로 검증해야 한다. 특히 한국어 설명의
품질과 반복 약점 분석이 기존 서비스 대비 얼마나 유용한지 확인해야 한다.

### 4.2 분석 작업 흐름

1.  사용자가 PGN 파일을 업로드하거나 지원 플랫폼에서 대국을 가져온다.
2.  Spring Boot API가 입력을 검증하고 대국 메타데이터를 저장한다.
3.  분석 요청을 작업 큐에 등록한다.
4.  Python 분석 워커가 PGN을 파싱하고 Stockfish로 주요 포지션을
    분석한다.
5.  분석 계층이 실제 수와 추천 수의 차이, 평가치 변화, 관련 변형을
    구조화한다.
6.  LLM 계층이 구조화된 근거를 바탕으로 자연어 해설을 생성한다.
7.  결과를 데이터베이스에 저장하고 프론트엔드에서 분석 상태와 결과를
    제공한다.
8.  여러 대국의 분석 결과가 누적되면 집계 모듈이 반복 패턴과 기간별
    변화를 계산한다.
9.  리포트 생성기가 분석 결과를 요약하고, 사용자는 리포트에 대해 대화형
    질문을 할 수 있다.

### 4.3 비동기 처리 설계

Stockfish 분석은 대국 길이와 분석 깊이에 따라 시간이 오래 걸릴 수 있다.
따라서 HTTP 요청에서 모든 분석을 동기적으로 끝내기보다 작업 큐를
이용하는 편이 적절하다.

-   API 서버: 분석 요청을 검증하고 작업을 등록한다.
-   RabbitMQ: 대기 중인 분석 작업을 전달한다.
-   분석 워커: 작업을 가져와 엔진 분석을 실행한다.
-   데이터베이스: 작업 상태와 결과를 기록한다.
-   프론트엔드: 작업 상태를 주기적으로 조회하거나 SSE 등으로 진행 상황을
    수신한다.

초기 버전은 모듈을 논리적으로 분리하되, 운영 복잡도를 줄이기 위해 반드시
모든 구성 요소를 독립 마이크로서비스로 배포할 필요는 없다.

### 4.4 LLM 근거 연결 설계

LLM에 "이 포지션을 분석해줘"라고만 요청하면 잘못된 수순이나 근거가
부족한 설명이 생성될 수 있다. 이를 줄이기 위해 분석 계층에서 다음과 같은
구조화된 데이터를 전달한다.

-   현재 포지션의 FEN
-   실제 착수와 엔진 추천 수
-   엔진 평가치와 평가치 차이
-   주요 후속 변형
-   관련 전술·전략 특성
-   설명에 사용 가능한 근거와 제한 사항

LLM은 이 데이터를 바탕으로 설명을 생성하며, 언급한 수순이 실제 엔진
변형과 일치하는지 검증하는 단계를 둔다. 근거가 부족한 경우 원인을
단정하지 않고 불확실성을 표시한다.

## 7. 시장성 및 수익 모델

### 7.1 시장성 가설

기존 서비스가 대국 분석, 자연어 코칭, 장기 통계 및 개인화 훈련 기능을
제공하고 있다는 점은 체스 학습 도구에 대한 실제 제품 생태계와 유료화
모델이 존재함을 보여준다. 다만 경쟁 서비스의 존재만으로 신규 서비스의
수요나 수익성을 입증할 수는 없다.

시장성을 검증하려면 다음을 조사한다. - 초보·중급 플레이어가 현재 분석
도구에서 느끼는 불편 - 한국어 설명에 대한 실제 선호와 지불 의사 - 여러
대국에 걸친 반복 약점 분석의 체감 가치 - 기존 서비스 대비 더 자주
사용하게 되는지 여부 - 코치가 학생별 자동 리포트를 도입할 의향이 있는지
여부

### 7.2 수익 모델 후보

**B2C Freemium** - 무료: 월간 분석 대국 수 또는 고급 리포트 기능 제한 -
유료 구독: 장기 분석, 대화형 질의, 상세 리포트, 개인화 훈련 추천, 분석
이력 비교

**B2B 코치용** - 학생별 대국 관리 - 학생별 반복 약점 및 개선 추이 -
수업용 리포트 내보내기 - 여러 학생의 진행 상황 대시보드

가격은 경쟁 서비스와 사용자 인터뷰, 실험 결과를 바탕으로 결정한다. 초기
기획 단계에서 임의의 시장 규모나 매출 전망을 확정적인 사실처럼 제시하지
않는다.

### 7.3 초기 검증 계획

1.  체스 초보·중급 사용자 10\~15명 인터뷰
2.  사용자가 직접 업로드한 기보로 분석 결과 프로토타입 제공
3.  설명의 이해도, 신뢰도, 유용성 평가
4.  기존 도구로 해결되지 않은 문제와 실제 재사용 의향 조사
5.  무료 사용 이후 유료 기능에 대한 지불 의사 테스트

## 12. 최종 제안

**프로젝트명:** ChessInsight AI\
**주제:** 대화형 체스 코칭 및 실력 분석·자동 리포팅 플랫폼

이 프로젝트의 핵심은 단순히 엔진의 최선 수를 알려주는 것이 아니다. 엔진
분석을 검증 가능한 근거와 함께 설명하고, 여러 대국에서 반복되는 취약점을
찾아내며, 사용자가 대화형으로 원인을 탐색하고 개선 여부를 추적하도록
만드는 것이다.

기술적으로는 Stockfish 기반 분석, Python 체스 데이터 처리, Spring Boot
API, 비동기 작업 큐, PostgreSQL, LLM 기반 자연어 설명을 결합할 수 있다.
AI와 백엔드 양쪽에서 구현 과제가 분명하며, 엔진 분석과 생성형 AI의
역할을 분리해 결과의 신뢰도를 평가할 수 있다는 장점이 있다.

사업적으로는 기존 경쟁 서비스와의 기능 중복을 인정하고, **근거가 연결된
장기 패턴 분석과 대화형 학습 워크플로**가 실제 사용자에게 더 큰 가치를
주는지 검증하는 것이 중요하다. 따라서 초기 MVP는 PGN 업로드, 엔진 분석,
근거 기반 해설, 반복 약점 요약, 기간별 리포트에 집중하고 사용자 테스트를
통해 확장 우선순위를 결정한다.
